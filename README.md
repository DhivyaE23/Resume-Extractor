# Resume Information Extractor

A full-stack Python application for reviewing text-based PDF resumes. It extracts contact details, skills, education, experience, dates, and organizations, then compares recognized resume skills with the skills listed in a job description.

The project includes a browser-based recruiter workspace and a FastAPI JSON API. It is intended as an assistive screening tool: extracted details and skill matches should be reviewed by a person and are not a hiring recommendation.

## How It Works

1. A reviewer enters a job description and uploads one PDF resume.
2. The API validates that the upload is a PDF no larger than 4 MB and that the job description is no larger than 64 KB, then writes the PDF to a temporary file.
3. PyMuPDF extracts page text in reading order. PyPDF2 is available as a fallback.
4. Regular expressions, section headings, spaCy named-entity recognition, and a known-skill vocabulary identify candidate fields.
5. The service calculates a skill match score and returns the extracted profile, matched skills, and missing recognized skills.
6. The temporary PDF is deleted after extraction. It is not saved as a candidate record.

For image-only scanned PDFs, OCR is attempted only when Tesseract is installed and available on `PATH`. Otherwise, the API reports that selectable text was not found. Install Tesseract separately if scanned-resume OCR is required.

## Features

- Light-theme responsive web interface for resume review
- Editable job-description starters for software engineering, frontend, backend/API, data analytics, machine learning, cloud/DevOps, and database engineering
- PDF text extraction with layout-aware ordering and a fallback reader
- Candidate name, email address, and phone number extraction
- Technical skill detection with token boundaries and common aliases such as HTML5/HTML and CSS3/CSS
- Education and experience extraction guided by resume section headings
- Organization extraction and date extraction with nearby resume context and section labels
- Skill matching against a pasted job description
- Domain starter descriptions can be loaded into the job-description editor and customized before analysis
- Standalone extraction and matching APIs, plus a combined analysis endpoint
- 4 MB PDF and 64 KB job-description limits, suitable for Vercel's 4.5 MB request-body limit
- Temporary-file cleanup after PDF extraction
- `/health` endpoint for hosting-provider health checks
- OpenAPI documentation generated by FastAPI at `/docs`

## Matching and Extraction Notes

- Skills are selected from the vocabulary in `app/skills.py`; unlisted skills are not matched.
- The score is the percentage of recognized job-description skills also found in the resume. It does not evaluate seniority, quality of experience, context, or candidate suitability.
- Name, education, experience, and organization extraction use heuristics. Resume layouts and wording vary, so results can be incomplete or occasionally incorrect.
- Scanned PDFs require the external Tesseract executable. Installing Python requirements alone does not install Tesseract.
- The application does not provide user accounts, persistent candidate records, or a database.

## Run Locally

From the project root, create and activate a virtual environment, then install dependencies:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Start the application:

```powershell
python -m uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000/`. Interactive API documentation is at `http://127.0.0.1:8000/docs`, and the health endpoint is `http://127.0.0.1:8000/health`.

## API Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Serves the resume-review web interface. |
| `GET` | `/health` | Returns `{"status":"ok"}` when the service is running. |
| `POST` | `/extract-resume` | Accepts multipart field `file` and returns extracted profile fields. |
| `POST` | `/match-resume` | Accepts multipart fields `file` and `job_description`; returns score, matched skills, and missing skills. |
| `POST` | `/analyze-resume` | Accepts the same fields and returns profile and matching results together. |

Upload endpoints require a PDF file. Matching endpoints require a non-empty job description containing at least one recognized skill. Errors include unsupported file type, oversized file, unreadable PDF, and no recognized job skills.

Extracted `dates` are returned as entries with `date`, `context`, and `section` fields. Context is taken from the date's line or nearby resume lines; `section` is `Experience`, `Education`, another detected section, or `null` when no section is recognized.

## Run Tests

Run the extraction, matching, and API regression tests from the project root:

```powershell
python -m unittest discover -s tests -v
```

## Deploy on Vercel Hobby

The repository is structured as a FastAPI application. Vercel's Python runtime recognizes `app/main.py` as an application entrypoint and detects Python dependencies from `requirements.txt`.

1. Push the project to a GitHub repository and sign in to Vercel.
2. Select **Add New > Project**, then import the Resume-Extractor repository.
3. Keep the repository root as the Root Directory. Let Vercel detect the FastAPI/Python project; do not enter a Uvicorn start command because Vercel runs it as a Function.
4. Select the Hobby plan and deploy. The `.python-version` file selects Python 3.13.
5. When the deployment completes, open the assigned `vercel.app` URL. Check `/health` and `/docs` as well as the homepage.

The Hobby plan is Vercel's free tier for eligible personal projects; review Vercel's current plan terms for your intended use. Vercel Functions limit each request body to 4.5 MB, so this app caps the PDF at 4 MB and the job description at 64 KB to leave room for multipart form overhead. Scanned PDFs need the external Tesseract executable, which is not included in the standard Vercel Python runtime; use text-selectable PDFs on this deployment.

## Privacy and Repository Hygiene

Uploads are processed from temporary files and removed after text extraction; this application does not retain resumes in a database. Use HTTPS in production and do not commit candidate resumes, job descriptions containing private data, or environment secrets. Local resume PDFs and `job_description.txt` are excluded by `.gitignore`.
